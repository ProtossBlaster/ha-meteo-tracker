# Meteo Tracker v0.3.0 — translated weather alert types

Released 2026-09-05. Includes [PR #7](https://github.com/ProtossBlaster/ha-meteo-tracker/pull/7),
with French translations contributed by @minimicro34.

## What changes

The existing weather alert type sensor now exposes stable lowercase keys for 17
known OpenWeather tags. Home Assistant can display English, Italian or French
labels according to the user's UI language. For example, the technical state
`extreme_high_temperature` is displayed as `Canicule` in French.

The new `raw_type` attribute retains the original OpenWeather tag. Future unknown
tags remain unchanged in both the state and attribute. With no active alert, the
state is `unknown` and `raw_type` is null. Full alert text is passed through as
OpenWeather supplies it; this integration does not translate that text.

Entity IDs, unique IDs and configuration are preserved. No additional sensor is
created. Existing history is retained; it can contain old raw values followed by
the new state keys. This release does not change API requests or refresh intervals.

## Upgrade

1. Create a Home Assistant backup before updating.
2. Update Meteo Tracker to v0.3.0 in HACS, then restart Home Assistant.
   For manual installations, replace `custom_components/meteo_tracker` with the
   directory from this release and restart Home Assistant.
3. If an automation or template compares a known old state, update it using the
   table below, or compare the `raw_type` attribute instead.
4. Check the sensor in Developer Tools → States. The technical state and
   `raw_type` differ for known tags. No active alert normally means `unknown`.

No automation changes are needed if you do not compare this sensor's old state.
Dashboard labels follow the Home Assistant UI language, independently of the
language configured for OpenWeather data.

| Previous state / `raw_type` | New technical state |
|---|---|
| Coastal event | `coastal_event` |
| Extreme low temperature | `extreme_low_temperature` |
| Extreme high temperature | `extreme_high_temperature` |
| Wind | `wind` |
| Flood | `flood` |
| Sand dust | `sand_dust` |
| Rain | `rain` |
| Fire warning | `fire_warning` |
| Marine event | `marine_event` |
| Avalanches | `avalanches` |
| Fog | `fog` |
| Air quality | `air_quality` |
| Tornado | `tornado` |
| Cyclone | `cyclone` |
| Snow ice | `snow_ice` |
| Thunderstorm | `thunderstorm` |
| Hail | `hail` |

Replace the example entity ID below with your actual per-person sensor ID.

Previous template:

```jinja
{{ is_state('sensor.example_weather_alert_type', 'Extreme high temperature') }}
```

New state comparison:

```jinja
{{ is_state('sensor.example_weather_alert_type', 'extreme_high_temperature') }}
```

Alternatively, compare the provider value:

```jinja
{{ state_attr('sensor.example_weather_alert_type', 'raw_type') == 'Extreme high temperature' }}
```

For a state trigger, change its `to` value to the new key. To trigger on the
original tag instead, specify `attribute: raw_type` and keep the original `to` value.

## Validation

- 63 automated tests cover the pure helpers, state mapping, future-tag fallback,
  malformed/empty inputs and EN/IT/FR catalogue consistency.
- A smoke test using the Home Assistant stable Docker image verifies state
  publication, raw attributes, no-alert transitions and stable unique IDs.
- HACS, Hassfest and pure-logic CI validate the release commit and tag.

The automated checks do not replace visual testing of every translated label in
each Home Assistant UI version.

## Rollback

Restore the pre-update Home Assistant backup, or reinstall the v0.2.4 integration
files and restart Home Assistant. Restore old state comparisons if you changed
automations for v0.3.0; v0.2.4 does not expose `raw_type`. Reinstalling alone does
not rewrite recorded history. Do not delete and recreate the integration.

## Italiano

La versione 0.3.0 traduce le etichette dei 17 tipi di allerta in italiano, inglese
e francese. Lo stato tecnico diventa stabile e minuscolo: ad esempio `Wind`
diventa `wind`. Il valore originale resta nell'attributo `raw_type`.

Aggiorna da HACS e riavvia Home Assistant. Se usi automazioni o template che
confrontano il vecchio stato, sostituiscilo secondo la tabella oppure confronta
`raw_type`. Se non hai queste automazioni, non occorrono modifiche.

Entità, identificativi, configurazione e storico restano disponibili. I tipi
futuri sconosciuti mantengono il valore originale; senza allerte lo stato è
`unknown`. Il testo completo dell'avviso rimane quello fornito da OpenWeather.

Prima dell'aggiornamento crea un backup. Per tornare indietro, ripristinalo oppure
reinstalla la 0.2.4 e riavvia, ripristinando anche gli eventuali confronti nelle
automazioni: la 0.2.4 non dispone di `raw_type`.
