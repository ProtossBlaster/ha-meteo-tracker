# Meteo Tracker v0.3.2 — forecast timelines that keep failing

Released 2026-10-30. Includes [PR #11](https://github.com/ProtossBlaster/ha-meteo-tracker/pull/11)
by @minimicro34, which fixes [#10](https://github.com/ProtossBlaster/ha-meteo-tracker/issues/10).

## What changes

Only keys on One Call 4.0 are concerned: there, the minute-by-minute, hourly and daily
forecasts are read with requests of their own. When one of them fails, for example the
daily forecast with "no answer within 30 s", the refresh goes on with the other data,
as before. Meteo Tracker used to log a warning on every refresh where that happened:
#10 counted 11 of them in about 6 hours.

Now the first failure is logged as a warning, later consecutive ones at debug level
with the attempt number, and the forecast's return at info level, with the number of
failed attempts. The count belongs to a place and a timeline: when several people are
tracked, a forecast that keeps failing for one place is not reset by one that works
for another. The count is held in memory and starts over when Home Assistant restarts.

Nothing else changes: the failing forecast is still requested on every refresh, and
entities, states, attributes, configuration and refresh intervals are those of v0.3.1.
Keys on One Call 3.0 are not concerned: 3.0 returns the forecasts with the rest of the
weather, in one request.

## Upgrade

1. Update Meteo Tracker to v0.3.2 in HACS, then restart Home Assistant. For manual
   installations, replace `custom_components/meteo_tracker` with the directory from
   this release and restart Home Assistant.
2. No configuration or automation changes are needed.

## Validation

- Pure-logic tests, including repeated failures, recovery, and two places sharing
  one client.
- HACS and hassfest validation in CI.

## Rollback

Reinstall v0.3.1 from HACS and restart Home Assistant. This release stores nothing
that v0.3.1 would not read.
