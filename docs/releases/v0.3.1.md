# Meteo Tracker v0.3.1 — weather alerts OpenWeather cannot read

Released 2026-10-04. Includes [PR #9](https://github.com/ProtossBlaster/ha-meteo-tracker/pull/9)
by @minimicro34, which fixes [#8](https://github.com/ProtossBlaster/ha-meteo-tracker/issues/8).

## What changes

Only keys on One Call 4.0 are concerned: there, each active weather alert is read with
a request of its own. OpenWeather sometimes answers that request with HTTP 404
(`Internal error`) for an alert it still lists, hour after hour. Meteo Tracker used to
ask for such an alert again on every refresh, logging a warning and paying a call each
time: five of them at the 10-minute default cost 720 calls a day, on top of the 864 the
refreshes of one place already cost, against the 1,000 free ones.

Now an alert that answers 404 is asked for again after 5, 10, 20 and 40 minutes, then
hourly: five of them cost 120 calls a day. The first failure is logged as a warning,
later ones at debug level, and the alert's return at info level. Everyone tracked
under the same alert shares one wait, and an alert that drops out of OpenWeather's
list keeps its wait until nobody has seen it for an hour. The Refresh button respects
the wait. The wait is held in memory and starts over when Home Assistant restarts.

A request that times out now says so in the log: "Error talking to OpenWeather: no
answer within 30 s", where it used to end after the colon.

Nothing else changes: entities, states, attributes, configuration and refresh
intervals are those of v0.3.0. Keys on One Call 3.0 are not concerned: 3.0 returns the
alerts with the rest of the weather, in one request.

## Upgrade

1. Update Meteo Tracker to v0.3.1 in HACS, then restart Home Assistant. For manual
   installations, replace `custom_components/meteo_tracker` with the directory from
   this release and restart Home Assistant.
2. No configuration or automation changes are needed.

## Validation

- Pure-logic tests, the alert wait included: CI now installs aiohttp, without which
  those tests were skipped.
- HACS and hassfest validation in CI.

## Rollback

Reinstall v0.3.0 from HACS and restart Home Assistant. This release stores nothing
that v0.3.0 would not read.
